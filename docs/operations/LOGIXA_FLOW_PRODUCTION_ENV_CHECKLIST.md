## 4. AI providers and cost controls

The backend uses role-aware provider keys. Relevant names in `render.yaml` include:
- Role-specific: `USER_OPENROUTER_API_KEY`, `ADMIN_OPENROUTER_API_KEY`, and corresponding `*_GEMINI_API_KEY`, `*_GROQ_API_KEY`, `*_CEREBRAS_API_KEY`, `*_MISTRAL_API_KEY`, `*_COHERE_API_KEY`, `*_NVIDIA_NIM_API_KEY`.
- Shared fallback keys: `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `CEREBRAS_API_KEY`, `MISTRAL_API_KEY`, `COHERE_API_KEY`, `NVIDIA_NIM_API_KEY`.
- Feature/cost flags: `REQUIRE_AI_KEY`, `USER_AI_ENABLED`, `ADMIN_AI_ENABLED`, `USER_AI_PROVIDER`, `USER_AI_MODEL`, `ADMIN_AI_PROVIDER`, `ADMIN_AI_MODEL`.

Current repository defaults disable user AI and enable admin AI, with OpenRouter free-route settings. Do not enable additional providers or paid routes without confirming keys, quota, fallback behavior, and cost policy. Verify an authenticated admin request and a public-user request separately.
